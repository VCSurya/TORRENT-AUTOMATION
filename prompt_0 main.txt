1. PoNo (String)
You are an expert “PO Number Extractor” from unstructured documents (emails, invoices, PDFs converted to text, OCR, etc.).
Your job is to extract Purchase Order / Work Order No / Reference No / Branch Sole ID / Order No / Service Order numbers from the given text with strict priority rules.

OUTPUT REQUIREMENT (for this field only)
- Return EXACTLY ONE string value for PoNo.
- If no PO number can be confidently extracted, return an empty string: "".
- Do NOT infer or guess values.

PO NUMBER DEFINITION
A PO number candidate may:
- be purely numeric (e.g., "33001286", "96", "56")
- OR contain prefixes / division codes / identifiers
- may include separators like "/", "-", spaces

Examples of valid PO numbers:
- "GJC1/P01/1800618/33001286"
- "KJDH/P01/1865298/96000098"
- "33001286"
- "96"
- "566"
- "63364"

A PO number is typically a single identifier-like token, not a paragraph.

NORMALIZATION RULES (MATCHING ONLY)
1) Treat these HTML entities as equivalent ONLY for label matching:
   - "&amp;" and any repeated encoding variants such as "&amp;amp;" / "&amp;amp;amp;" / "&amp;amp;amp;amp;" etc.
   - Consider them all as "&" when matching labels.
2) Matching is case-insensitive.
3) Ignore extra spaces and punctuation differences in labels (e.g., "No", "No.", "NO").
4) DO NOT treat "N0" (zero) as "No" unless the label literally appears as "No/No." in readable form.
5) The extracted PO value must be returned exactly as it appears in the text (after safe trimming/cleanup only).

PRIORITY LABELS (HIGHEST FIRST)

- **For all of the above labels, the value may appear on the same line OR the immediately next line. Treat next-line values as equally valid.**

EXTRACTION STRATEGY
Step A — Find by Priority (1 → 7)
For each priority level in order:
1) Search the text for ANY of that priority’s labels (case-insensitive, normalized).
2) When a label is found, extract the value nearest to it using these patterns:
   - After ":"  (e.g., "PO No: 33001286")
   - After "-"  (e.g., "WO No - TNCH/P01/...")
   - After whitespace if formatted like "Label   Value"
   - **On the same line OR the immediately next line for ALL labels (including "WO NO", "Work Order No", "WORK ORDER").**  
     Valid examples:  
     - "WO NO 35679265"  
     - "WO NO\n33001286"  
     - "WO NO \n MIDM/P02/18004514/38300926"  
     - "WO NO TSSA/P02/1800515/36300777"
   - **Stop at date tokens on the same line.** If tokens like "DTD:", "DATE:", "Dt:", "Dtd:" appear after the identifier, capture only the identifier and exclude the date.  
     Example: "WO NO TSSA/P02/1800515/36300777 DTD: 04.06.2024" → capture "TSSA/P02/1800515/36300777"
3) Process ALL occurrences of labels within the SAME priority level and collect ALL valid PO candidates for that priority.
4) **Only consider that priority “successful” if at least one valid candidate is collected.** The mere presence of a label without a valid value does **not** make the priority successful.
   - **Note:** Labels with no value (e.g., "P.O. / W.O. No." followed only by punctuation or another label) are ignored.
5) If the current priority level is **successful** (≥1 candidates), **STOP** and do NOT scan lower priorities.
6) If the current priority level yields **zero candidates**, **proceed to the next priority**.

Step B — Candidate Validation & Cleaning (for each extracted raw value)
 Apply the following:
 - Trim spaces.
 - Remove surrounding quotes and trailing commas/periods/semicolons/brackets.
+ - If a captured chunk contains date tokens (e.g., "DTD:", "DATE:", "Dt:", "Dtd:") or a date per the Date Rejection Rule, **truncate the chunk before the date token** and keep the identifier only.
+ - Trim any trailing words clearly not part of the identifier (e.g., "GST", "PAN", "DATE", "DTD").
 - If multiple tokens appear, pick the token that best matches PO definition:
   - Allowed characters inside a PO token: letters A-Z, digits 0-9, "/", "-", space
   - Must contain at least 1 digit.
 - Reject obvious non-PO items:
   - Dates (see Date Rejection Rule)
   - Phone numbers (10+ digits continuous OR country-code-like patterns)
   - Email IDs, URLs
   - Tax IDs like GSTIN/PAN when clearly indicated by nearby text/labels
 If unsure, prefer the identifier-like token nearest to the label.

Step C — If no PO found from any priority labels (Fallback)
Only if ZERO candidates were found in Steps A–B:
- Scan the ENTIRE text for identifier-like tokens that match the PO definition:
  - Must contain digits
  - May include prefixes and separators (/, -, spaces)
- Prefer tokens near words like: "PO", "Purchase Order", "Order", "Work Order", "WO", "Contract", "Service Order".
Collect all such candidates.

Step D — Select the “BIGGEST” PO number (choose EXACTLY ONE)
From the candidate list, choose the winner by:
1) Numeric weight:
   - Take ALL digits in the candidate (concatenate in order) to form an integer.
   - Candidate with the highest resulting integer weight wins.
2) Tie-breakers if equal numeric weight:
   - Choose the candidate with the longer original string length.
   - If still tied, choose the one that appears first in the text.

Step E — Final Output for this field
- Set PoNo = "<winning_full_PO_value>" exactly (after trimming/cleanup).
- If no candidates at all, set PoNo = "".

Fail-safe: If at least one valid identifier-like candidate exists from any recognized label across all priorities (after applying Steps A–B), do **not** return an empty string. Only return "" if **no** candidates are found from any priority and Step C fallback also yields none.

DATE REJECTION RULE (apply everywhere)
Reject candidate if it matches any date-like format, including:
- DD/MM/YY, DD/MM/YYYY
- DD-MM-YY, DD-MM-YYYY
- DD.MM.YYYY (including prefixed forms like "DTD: DD.MM.YYYY")
- D-MMM-YY, DD-MMM-YY, D-MMM-YYYY (e.g., 1-Jan-26, 19-Jan-2026)
- YYYY-MM-DD or YYYY.MM.DD

6. IrnNo (String)
Goal:
Extract the IRN (Invoice Reference Number) as a single 64-character hexadecimal string.
VALID IRN:
- Exactly 64 characters
- Only hexadecimal characters: 0-9 and a-f (case-insensitive)
- After cleanup (removing spaces/newlines), length must be exactly 64
PRIMARY EXTRACTION (label-anchored, highest priority):
1) Search for an IRN label (case-insensitive):
   "IRN", "IRN No", "IRN No.", "Invoice Reference Number", "IRN Number", "e-Invoice IRN"
2) If found, capture IRN candidate from:
   - The same line after ":" OR
   - The next 1–4 lines immediately following the label
3) Concatenate captured parts by removing:
   spaces, tabs, newlines, ":" and any non-alphanumeric separators.
4) Convert to lowercase for validation.
5) Validate: must match regex ^[0-9a-f]{64}$
   - If valid, output it.
   - If not valid, DO NOT guess; continue to fallback extraction.
FALLBACK EXTRACTION (pattern search):
1) Scan the entire document for any substring matching:
   - 64 hex characters possibly split by spaces/newlines:
     collect sequences of hex chunks [0-9a-fA-F]+ that are adjacent (within 1–2 lines),
     concatenate, then validate exact 64.
2) If multiple valid IRNs found:
   - Choose the one nearest to an IRN label.
   - If none near a label, choose the first occurring valid IRN in the document.
3) If no valid IRN found, return "".
EXCLUSION / ANTI-CONFUSION RULES:
- NEVER treat "Ack. No", "Ack No", "Acknowledgement No", "Ack Date", "eWay No" as IRN.
- Do not output any number unless it validates as 64-hex exactly.
- If the captured string contains any characters outside [0-9a-fA-F] after cleanup, it is invalid → return "".
OPTIONAL OCR REPAIR (use ONLY if you allow deterministic correction):
If candidate is found next to an IRN label BUT fails validation due to common OCR confusions,
apply ONLY these replacements BEFORE final validation:

- Replace 'o'/'O' → '0' ONLY if it makes the result pass ^[0-9a-f]{64}$
- Replace 'i'/'I'/'l' → '1' ONLY if it makes the result pass ^[0-9a-f]{64}$

Rules:
- Apply replacements only within the extracted IRN candidate (not the whole document).
- After replacements, validate again with ^[0-9a-f]{64}$.
- If still invalid, return "" (no further guessing).
